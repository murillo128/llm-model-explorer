# Input embedding analysis evidence

## Numerical source and independent oracles

`api/fixtures/embedding-analysis.json` is generated by the independent API
validator, without importing backend or UI implementations. Its main table is
`[[-4,0,4],[-1000,0,1000],[1,2,3]]`; IDs `[2,0,2]` select
`[[1,2,3],[-4,0,4],[1,2,3]]`. The derived domain is `[-4,4]`, finite count is 9,
and mean is `4/3`. The unused vocabulary row cannot affect these results.

The fixture set also covers singleton/empty requests, constants, mixed and
all-nonfinite values, and opposite-sign float32 extremes with a small residual.
Raw source bytes preserve nonfinite values without non-standard JSON. Statistics
use independent float64 reference reductions and the accepted tolerances; raw
values, extrema and every uint32 histogram count are compared exactly.

## Runtime and protocol checks

`backend/tests/test_embedding_analysis.py` exercises both actual HTTP routes,
including real TCP delivery with three independently controlled auxiliary
consumers while embedding values complete. It checks invalid IDs before headers,
unsupported resolution, source mutation, control/shape bounds, count overflow,
resource failures, cancellation before META and after DATA, disconnect and session
deletion. The common writer rejects every statistics DATA frame, including empty.

Requested-row instrumentation forbids complete-table iteration and checks bounded
chunks across a wide row. Repeated successful requests leave no persistent numeric
cache entries or temporary artifact directories. Weak references establish release
of both input and count buffers. Blocking-read and queued-device tests establish
that cancellation settles work before cleanup and that gathering precedes queue
acquisition. The queue test uses CPU kernels under an instrumented device lock;
it is not actual CUDA evidence.

The UI API tests consume the shared schema/wire fixtures under every two-part
split, one-byte and varied chunk boundaries. Typed client tests check POST bodies,
identity snapshots, wrong ordered echoes with the same shape, wrong kinds,
independent operation cancellation and successful completion only after clean EOF.
Existing tensor, embedding-value and architecture fixtures remain unchanged.

## Reproduction and limits

Use the locked backend environment for `ruff check .`, `ruff format --check .`,
`mypy`, and `pytest`. Focused tests are `test_embedding_analysis.py`,
`test_tensor_analysis.py`, `test_embeddings.py` and `test_lmex.py`.
Run `python api/validate_contract.py` with `api/requirements.txt`, and run
`npm run api:check`, `npm run typecheck`, `npm run lint`, `npm test -- src/api`,
and `npm run build` in `ui/`.

CPU fixture validation is mandatory. Actual CUDA is explicitly skipped when no
CUDA device is available; optional local-checkpoint validation was not configured
for this run. No claim of new model-family admission or full local reference
acceptance follows from these fixtures. Tokenizer controller/card integration
remains a separate increment consuming these typed operations.
